## 2. 아키텍처 — 40초 (책임 표는 짚기만)

**스크롤 위치** : 모듈 관계 그림이 화면 가운데 → 그다음 책임 표

**말할 것** (그림을 위 → 아래로)
- 위 상자 : "앱은 오목입니다. `App` 이 화면을 `h()` 로 적고, Hook 으로 상태를 씁니다."
- 아래 상자 다섯 개 : "엔진은 다섯 파일입니다."
	- `vdom` : 화면을 객체로 적는다
	- `diff` : 두 객체를 비교해 변경 목록을 만든다
	- `patch` : 그 목록대로 실제 DOM 을 고친다
	- `hooks` : 부른 순서대로 상태를 저장한다
	- `component` : 이 한 바퀴를 돌리는 지휘자
- 표 아래 마지막 줄 : "엔진 세 버전은 `vdom` · `diff` · `patch` 가 똑같고, 배칭을 맡은 두 파일만 다릅니다."

**강조** : diff 는 만들기만, patch 는 쓰기만 — 변경 목록이 둘 사이의 약속

## 3. 핵심 실행 흐름 및 설계 결정 — 70초

**스크롤 위치** : 순서도 → 설계 결정 표 → 측정 표 (함수 이름 표는 지나간다)

- 가로 메모 : "지금 실행 중인 코드가 끝나면,"
- 3–10 : "`App` 을 다시 실행하고, 엔진이 자식까지 펼쳐 새 VDOM 을 만든 뒤 diff, patch, effect 순서로 반영합니다."

**설계 결정 (25초)** — 표 네 줄을 위에서부터
- 문제 : "setter 마다 렌더하면 두 번 그리고, 그 사이 맞지 않는 중간 화면이 생깁니다."

- 이유 : "v1 은 엔진이 붙인 이벤트 핸들러만 자동으로 묶어서, 타이머나 `await` 뒤는 직접 감싸야 했습니다."

# Mini DBMS 구조

## Phase 1 — SQL 처리기

### 요청 흐름

`main.c` → `cli.c` → `db_open` → `db_execute_sql` → `result_print_text` → `db_close` 순서다. CLI는 옵션과 SQL 입력만 처리하며 SQL 실행은 반드시 `db_execute_sql`을 통한다. 입력을 끝까지 읽고 I/O 오류와 NUL 바이트를 검사한 뒤 데이터베이스를 연다. 파일 읽기 실패로 불완전한 SQL이 실행되는 것을 막는다. 시작의 UTF-8 BOM은 제거한다.

`db_open`은 데이터 폴더를 잠그고 `catalog.txt`를 읽어 모든 테이블을 연다. 카탈로그는 시작 이후 읽기 전용이다. 폴더와 카탈로그는 미리 있어야 하며 테이블 파일은 없으면 생성한다. 실패하면 이미 열린 테이블과 폴더 잠금을 해제한다.

`db_execute_sql`은 문자열·이스케이프·주석을 구분하여 문장을 나누고 각 문장을 `parse_sql`에 넘긴다. 내부 흐름은 lexer(줄·칸이 있는 토큰) → parser(Statement) → executor다. 뒤 문장의 구문 오류도 앞 문장의 실행을 취소하지 않는다. 첫 오류에서 멈추며 결과에는 성공한 문장만 남는다. 트랜잭션은 없다. `committed`는 성공한 문장 수이며 SELECT도 포함한다. 여러 행 INSERT 도중 I/O 오류가 나면 같은 문장 안에서도 앞 행이 남을 수 있고 오류 메시지에 그 수를 기록한다.

executor는 스키마·컬럼·타입·값 개수를 확인하고 INSERT 또는 SELECT를 수행한다. id는 자동 부여하며 사용자가 지정하면 오류다. Phase 1의 SELECT는 id 조건도 모두 선형 탐색(`plan=scan`)이다. 결과는 행, 실행 계획, 조사한 행 수, 소요 시간을 소유하고 `result_free`로 해제한다. CLI는 앞 결과와 위치 있는 오류를 출력하고 종료 코드 1을 반환한다. SQL 외의 입력·옵션 오류에는 위치 0:0을 쓴다. 카탈로그 오류는 카탈로그의 위치를 유지한다.

### 파일 형식과 불변식

- 카탈로그: 기본 `data/catalog.txt`, `테이블 : 컬럼 타입, ...` 형식. 첫 컬럼은 항상 `id INT`다.
- 테이블: `data/<table>.tbl`. `--data DIR`이면 해당 폴더 아래 같은 이름을 쓴다.
- 레코드: `[u32 payload 길이][u32 CRC32/IEEE][i64 id][필드들]`. 모든 정수는 리틀 엔디언이며 길이는 8바이트 헤더를 제외한다. CRC 범위는 id부터 payload 끝까지다.
- INT 필드: `[i64]`. TEXT 필드: `[u32 바이트 길이][바이트]`. 종결 NUL은 저장하지 않는다. TEXT는 최대 64 KiB, 헤더를 포함한 레코드는 최대 1 MiB다.
- id는 양수이며 파일 순서대로 증가한다. 시작 때 검사한 마지막 id의 다음 값을 사용한다. int64 범위를 소진하면 추가를 거부한다.

INSERT는 쓰기 락 안에서 파일 끝에 레코드를 추가한다. 기본 `sync always`는 동기화 성공 후에만 id와 성공 결과를 공개한다. `sync none`은 동기화를 생략하므로 장애 때 성공한 쓰기도 유실될 수 있음을 CLI가 표준 에러에 표시한다. 추가 또는 동기화 실패 시 이전 파일 끝으로 자르고 동기화하여 되돌린다. 되돌리기까지 실패한 테이블은 닫고 다시 열기 전까지 추가를 거부한다.

### 시작 복구와 실패 정책

시작할 때 파일 전체를 훑어 길이·CRC·필드 형식·id 증가를 검사한다. 끝의 헤더나 payload가 불완전하면 그 레코드 시작으로 자르고 동기화한다. 완전한 레코드의 CRC 오류, 잘못된 길이·필드·id 등 손상은 기본적으로 시작을 거부하며 파일 오프셋을 오류에 남긴다. `--repair`를 지정했을 때만 첫 손상 지점부터 이후를 모두 잘라낸다. 읽기·메모리 확보 같은 운영 실패는 repair로도 잘라내지 않는다.

폴더 잠금 파일 `.mini-dbms.lock`으로 다른 프로세스가 같은 데이터 폴더를 동시에 여는 것을 막는다. 종료 때 핸들과 잠금을 해제하며 잠금 파일 자체는 남을 수 있다. 현재 OS 계층은 프로세스당 하나의 열린 데이터베이스만 지원한다.

### 락과 결과 소유권

각 Table 안에 `pthread_rwlock_t`가 있다. executor가 SELECT에는 읽기 락, INSERT에는 쓰기 락을 잡는다. table 저장 함수는 내부에서 락을 중복 획득하지 않는다. 한 문장은 테이블 하나만 잠그므로 테이블 간 락 순환이 없다. 열기·닫기는 실행 요청과 동시에 수행하지 않는다.

읽기는 `os_read_at`의 위치 지정 읽기만 사용하여 공유 파일 커서를 움직이지 않는다. 행과 TEXT를 포함한 결과 전체를 락 안에서 요청 소유 메모리로 복사하고, 락을 푼 뒤 출력한다. 동시에 실행할 때 요청마다 별도의 Result를 사용한다. Windows와 POSIX 차이는 `os.c` 안에만 둔다.

### 검증 방법

`mingw32-make test`는 기존 C 단위 테스트와 `tests/run_cli_tests.py`를 실행한다. CLI 기능 테스트는 임시 폴더에 카탈로그를 복사하며 실제 실행 파일의 stdout과 종료 코드를 `tests/sql/*.expected`와 비교한다. expected 파일의 첫 줄은 `exit_code=N`, 이후는 stdout이다. 변동하는 실행 시간만 메타데이터 위치에서 `<time>`으로 치환하고 나머지 표·값·plan·조사 수·오류 위치는 그대로 비교한다.

파일 입력 6개와 표준 입력, 기본 옵션, 동기화 옵션, 재실행 후 id 유지, 빈 입력·BOM, 잘못된 인자·입력, 카탈로그 열기 실패, 끝 잘림 복구·CRC 손상 거부·명시적 복구, 중간 구문 오류의 앞 문장 보존, 1 MiB보다 긴 CLI 입력을 확인한다. 테스트 종료 시 임시 데이터 폴더를 정리한다.

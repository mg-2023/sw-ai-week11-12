# Mini DBMS 구조

## Phase 1 — SQL 처리기

### 요청 흐름

`main.c` → `cli.c` → `db_open` → `db_execute_sql` → `result_print_text` → `db_close` 순서다. CLI는 옵션과 SQL 입력만 처리하며 SQL 실행은 반드시 `db_execute_sql`을 통한다. 입력을 끝까지 읽고 I/O 오류와 NUL 바이트를 검사한 뒤 데이터베이스를 연다. 파일 읽기 실패로 불완전한 SQL이 실행되는 것을 막는다. 시작의 UTF-8 BOM은 제거한다. `run -`는 읽기 전에 `os_stdin_binary`를 호출한다. Windows에서는 `_setmode`로 이진 모드를 설정하여 0x1A와 CRLF를 파일 입력과 똑같이 읽으며 POSIX에서는 아무 작업도 하지 않는다.

`db_open`은 데이터 폴더를 잠그고 `catalog.txt`를 읽어 모든 테이블을 연다. 카탈로그는 시작 이후 읽기 전용이다. 폴더와 카탈로그는 미리 있어야 하며 테이블 파일은 없으면 생성한다. 실패하면 이미 열린 테이블과 폴더 잠금을 해제한다.

`db_execute_sql`은 문자열·이스케이프·주석을 구분하여 문장을 나누고 각 문장을 `parse_sql`에 넘긴다. 내부 흐름은 lexer(줄·칸이 있는 토큰) → parser(Statement) → executor다. 뒤 문장의 구문 오류도 앞 문장의 실행을 취소하지 않는다. 첫 오류에서 멈추며 결과에는 성공한 문장만 남는다. 트랜잭션은 없다. `committed`는 성공한 문장 수이며 SELECT도 포함한다. 여러 행 INSERT 도중 I/O 오류가 나면 같은 문장 안에서도 앞 행이 남을 수 있고 오류 메시지에 그 수를 기록한다.

executor는 스키마·컬럼·타입·값 개수를 확인하고 INSERT 또는 SELECT를 수행한다. id는 자동 부여하며 사용자가 지정하면 오류다. Phase 1의 SELECT는 id 조건도 모두 선형 탐색(`plan=scan`)이다. 결과는 행, 실행 계획, 조사한 행 수, 소요 시간을 소유하고 `result_free`로 해제한다. CLI는 앞 결과와 오류를 출력하고 종료 코드 1을 반환한다.

`DbError.kind`는 문법·의미·타입 오류인 `DB_ERROR_SQL`과 파일 I/O·메모리·락·저장 데이터 손상 등의 `DB_ERROR_INTERNAL`을 구분한다. SQL 오류는 기존 `error at L:C: …` 형식을 유지한다. 옵션 오류와 NUL 입력 오류는 위치 0:0이며 카탈로그 형식 오류는 카탈로그 위치를 유지한다. 내부 오류는 위치를 0:0으로 두고 `internal error: …`로 출력한다. executor나 문장 위치 보정이 내부 오류에 SQL 위치를 덧씌우지 않는다. 향후 서버가 종류에 따라 400/500을 선택할 수 있는 정보만 마련했으며 서버는 구현하지 않았다.

### 파일 형식과 불변식

- 카탈로그: 기본 `data/catalog.txt`, `테이블 : 컬럼 타입, ...` 형식. 첫 컬럼은 항상 `id INT`다. 테이블·컬럼 이름은 ASCII `[A-Za-z_][A-Za-z0-9_]*`이며 최대 63바이트다. lexer가 키워드로 분류하는 모든 단어(`INSERT`, `INTO`, `VALUES`, `SELECT`, `FROM`, `WHERE`, `LIMIT`)는 대소문자를 무시하고 이름으로 거부한다. lexer와 카탈로그가 `lex_identifier_kind`를 함께 호출하므로 키워드 목록은 lexer 한 곳에만 있다. 모든 플랫폼에서 대소문자를 무시한 중복 테이블 이름을 거부한다. SQL에서 이름을 찾는 동작은 기존처럼 대소문자를 구분한다.
- 테이블: `data/<table>.tbl`. `--data DIR`이면 해당 폴더 아래 같은 이름을 쓴다.
- 레코드: `[u32 payload 길이][u32 길이 검사값][u32 payload CRC32/IEEE][i64 id][필드들]`. 모든 정수는 리틀 엔디언이며 길이는 12바이트 헤더를 제외한다. 길이 검사값은 길이를 인코딩한 리틀 엔디언 4바이트의 `CRC32/IEEE XOR 0x4D444231`이다. payload CRC 범위는 id부터 payload 끝까지다. 기존 8바이트 헤더 및 `~길이` 검사값을 쓰던 12바이트 헤더 파일의 자동 변환은 제공하지 않는다.
- INT 필드: `[i64]`. TEXT 필드: `[u32 바이트 길이][바이트]`. 종결 NUL은 저장하지 않는다. TEXT는 최대 64 KiB, 헤더를 포함한 레코드는 최대 1 MiB다.
- id는 양수이며 파일 순서대로 증가한다. 시작 때 검사한 마지막 id의 다음 값을 사용한다. int64 범위를 소진하면 추가를 거부한다.

INSERT는 쓰기 락 안에서 파일 끝에 레코드를 추가한다. 기본 `sync always`는 동기화 성공 후에만 id와 성공 결과를 공개한다. `sync none`은 동기화를 생략한다. CLI는 실행 후 표준 오류에 마지막 동기화 뒤 쓴 행은 OS 장애 시 잃을 수 있다는 범위와 이번 실행의 실제 추가 행 수를 표시한다. 오류로 멈춘 INSERT에서 이미 추가된 행도 센다. 추가 또는 동기화 실패 시 이전 파일 끝으로 자르고 동기화하여 되돌린다. 되돌리기까지 실패한 테이블은 닫고 다시 열기 전까지 추가를 거부한다.

### 시작 복구와 실패 정책

시작할 때 파일 전체를 훑어 길이·CRC·필드 형식·id 증가를 검사한다. 오프셋 `off`에서 다음 순서로 분류한다.

1. 남은 바이트가 헤더 12바이트보다 적으면 끝 잘림이다.
2. `off`부터 파일 끝까지 전부 0이면 0으로 채워진 끝 잘림이다. 헤더만 0이고 뒤에 비영 바이트가 있으면 이 규칙에 해당하지 않는다.
3. 검사값이 길이 4바이트의 `CRC32/IEEE XOR 0x4D444231`과 다르거나 길이가 0 또는 상한 초과면 손상이다.
4. 정상 헤더의 본문이 파일 끝을 넘으면, 즉 `파일 끝 − off < 12 + 선언된 길이`이면 꼬리를 추가 검사한다. `off + 1`부터 바이트마다 헤더를 시도하여 허용 길이·길이 검사값·본문 CRC가 모두 맞고 파일 안에 온전히 들어 있는 레코드가 하나라도 있으면 손상이다. 후보의 필드 형식이나 id 순서와 무관하게 거부한다. 그런 레코드가 없을 때만 끝 잘림이다. 헤더 포함 레코드 상한이 1 MiB이므로 이 경우 꼬리는 1 MiB보다 작으며 기존 블록 버퍼 안에서 검사한다.
5. 본문이 모두 있는데 CRC가 다르면 손상이다. CRC가 맞아도 필드 형식이나 id 증가 규칙이 틀리면 손상이다.

끝 잘림은 `off`로 자르고 동기화한 뒤 표준 오류에 `N bytes of incomplete tail truncated at offset X`를 남긴다. 손상은 파일을 그대로 두고 시작을 거부하며 오프셋을 오류에 남긴다. `--repair`를 지정했을 때만 첫 손상 지점부터 이후를 모두 잘라낸다. 읽기·메모리 확보 같은 운영 실패는 repair로도 잘라내지 않는다.

폴더 잠금 파일 `.mini-dbms.lock`으로 다른 프로세스가 같은 데이터 폴더를 동시에 여는 것을 막는다. 없는 데이터 폴더는 잠금을 시도하기 전에 `data directory not found: …`로 보고한다. 종료 때 핸들과 잠금을 해제하며 잠금 파일 자체는 남을 수 있다. 현재 OS 계층은 프로세스당 하나의 열린 데이터베이스만 지원한다.

### 락과 결과 소유권

각 Table 안에 `pthread_rwlock_t`가 있다. executor가 SELECT에는 읽기 락, INSERT에는 쓰기 락을 잡는다. table 저장 함수는 내부에서 락을 중복 획득하지 않는다. 한 문장은 테이블 하나만 잠그므로 테이블 간 락 순환이 없다. 열기·닫기는 실행 요청과 동시에 수행하지 않는다.

읽기는 `os_read_at`의 위치 지정 읽기만 사용하여 공유 파일 커서를 움직이지 않는다. 행과 TEXT를 포함한 결과 전체를 락 안에서 요청 소유 메모리로 복사하고, 락을 푼 뒤 출력한다. 동시에 실행할 때 요청마다 별도의 Result를 사용한다. Windows와 POSIX 차이는 `os.c` 안에만 둔다.

`table_scan`과 시작 검사는 같은 블록 읽기를 사용한다. 요청별 1 MiB 입력 버퍼에 여러 레코드를 읽고 경계에 걸친 헤더·본문은 남은 바이트를 옮긴 뒤 다음 블록을 채운다. 행 해석용 필드와 NUL 종결 TEXT 작업 공간도 요청별로 한 번 확보하여 행마다 malloc하지 않는다. 방문자는 호출 중에만 Row를 빌리며 SELECT 결과는 별도로 복사한다. Windows 읽기 이벤트는 TLS로 스레드마다 한 개를 재사용하며 워커 종료 때 해제한다. OVERLAPPED와 읽기 버퍼는 공유하지 않는다.

`table_open_with_visitor`는 검증한 각 행의 `(id, 파일 오프셋)`을 파일 순서대로 호출자 콜백에 전달한다. 기존 `table_open`은 NULL 콜백을 쓰는 래퍼다. 콜백 실패는 내부 오류이며 repair로 파일을 자르지 않는다. 뒤 레코드에서 열기가 실패할 수 있으므로 콜백 상태와 실패 정리는 호출자 책임이다. 인덱스 구축은 이번 범위에 포함하지 않는다.

### 검증 방법

`mingw32-make test`는 기존 C 단위 테스트와 `tests/run_cli_tests.py`를 실행한다. CLI 기능 테스트는 임시 폴더에 카탈로그를 복사하며 실제 실행 파일의 stdout과 종료 코드를 `tests/sql/*.expected`와 비교한다. expected 파일의 첫 줄은 `exit_code=N`, 이후는 stdout이다. 변동하는 실행 시간만 메타데이터 위치에서 `<time>`으로 치환하고 나머지 표·값·plan·조사 수·오류 위치는 그대로 비교한다.

파일 입력 6개와 표준 입력, 기본 옵션, 동기화 옵션과 실제 추가 행 수, 재실행 후 id 유지, 빈 입력·BOM, 잘못된 인자·입력, 없는 데이터 폴더, 카탈로그 열기 실패·이름 중복·잘못된 이름·모든 lexer 예약어의 대소문자별 거부, 끝 잘림 복구·길이/검사값/CRC 손상 거부·명시적 복구, 0x1A 오류와 CRLF 저장 바이트 동등성, 중간 구문 오류의 앞 문장 보존, 1 MiB보다 긴 CLI 입력을 확인한다. 길이 검사값은 Python zlib으로 독립 대조하며 첫·중간 레코드에서 길이와 검사값의 같은 비트 32개를 각각 뒤집어 파일 보존을 확인한다. 끝 잘림 후보 안의 완전한 레코드는 바이트 정렬과 무관하게 거부하며 불완전한 후보·검사값 또는 CRC가 틀린 후보는 자동 복구를 막지 않는지 확인한다. C 테스트는 독립 이진 fixture, 최대 크기 레코드, 헤더·본문의 블록 경계, 시작 콜백의 id/오프셋과 실패, 동시 스캔 및 파일 커서 보존, 주입한 읽기·쓰기·동기화 실패를 확인한다. 테스트 종료 시 임시 데이터 폴더를 정리한다.

성능 재현은 `python tests/measure_scan.py`로 수행한다. `build/` 아래 새 임시 폴더에 CLI와 `--sync none`으로 20만 행을 넣고, `db_open` 시작 시간과 `db_execute_sql`의 `SELECT * FROM users WHERE name = 'user_199999'` 실제 결과를 세 번 출력한다. 프로세스 실행 시간은 시작 측정에서 제외되며 데이터 작성 직후의 OS 캐시가 따뜻한 상태다. 측정용 실행 파일·SQL·테이블은 완료 후 제거한다.

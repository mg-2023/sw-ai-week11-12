# Mini DBMS Implementation Plan

> **For agentic workers:** 구현자 = Codex. 작업(Task) 순서대로, 테스트 먼저. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 요구사항 노트의 필수 28개를 충족하는 C11 Mini DBMS (Phase 1 SQL 처리기 → Phase 2 B+ 트리 → Phase 3 스레드 풀 API 서버).

**Architecture:** lexer → parser → executor → table/bptree 를 단일 진입점 `db_execute_sql` 로 묶고, CLI · bench · HTTP 서버가 모두 그것만 부른다. 테이블은 길이 · CRC 접두 이진 추가 파일, 인덱스는 시작 때 재구축하는 메모리 B+ 트리. 서버는 accept 스레드 + 고정 워커 풀 + 테이블별 rwlock.

**Tech Stack:** C11, MinGW-w64 gcc 13 (posix, winpthreads), Winsock2, `mingw32-make`, Python 3 표준 라이브러리 (기능 · 서버 테스트 스크립트만)

**Spec:** `docs/design/2026-11-17-design.md` (v2). 요구사항 원본 : `D:\Program Files\Obsidian\storage\크래프톤정글\주차 학습\11-12주차 - 미니리액트, 레디스, DBMS\미니DBMS\요구 사항 분석.md`

## Global Constraints

- `CFLAGS = -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror`, 링크 `-pthread -lws2_32`
- 외부 C 라이브러리 금지 (표준 라이브러리, pthreads, Winsock, Win32 API 만)
- `_WIN32` 분기는 `src/os.c` 에만 둔다
- CLI · bench · HTTP 는 `db_execute_sql` 외의 실행 경로를 쓰지 않는다
- 카탈로그 파일 `data/catalog.txt`, 테이블 파일 `data/<table>.tbl`
- 레코드 = `[u32 길이][u32 CRC32][i64 id][필드들]`, TEXT = `[u32 길이][바이트]`, INT = `[i64]`, 리틀 엔디언. CRC 범위 = id 부터 끝. 레코드 상한 1MB, TEXT 상한 64KB
	- 구현 중 바뀜 : 지금 형식은 12바이트 헤더 (길이 검사값 추가) 와 메타 레코드 (FORMAT · COMMIT · ID_FLOOR) 다. 최신은 설계 `docs/design/2026-11-17-design.md` 2.6 과 v2.1 ~ v2.3 변경 기록, `docs/architecture.md` 를 따른다
- B+ 트리 차수 64
- 서버 기본 : 포트 8100, 워커 4, 큐 64, 본문 상한 1MB, 받기 2초, 전체 5초, 보내기 2초
- 커밋 메시지는 한국어, 본문에 "필요한 것 → 걸리는 것 → 그래서 한 것". Claude · Codex · AI 표시를 넣지 않는다
- push 하지 않는다

## Review Focus

1. 여러 스레드가 동시에 `WHERE id = ?` 를 보낼 때 각자 정확한 행을 받는다 → Task 13 `test_concurrent_index_reads`
2. 쓰다 멈춘 끝 레코드는 잘려 복구되고, 중간이 깨진 파일은 시작을 거부한다 → Task 5
3. NUL · 따옴표 · 역슬래시 · 잘못된 UTF-8 이 든 TEXT 가 JSON 을 깨지 않는다 → Task 12 `test_json_escape`
4. 느린 클라이언트 4개가 워커를 붙잡아도 다른 요청이 시한 안에 503 이나 응답을 받는다 → Task 13 `test_slow_clients`
5. INT 범위 넘침 · `LIMIT` 음수 · VALUES 개수 불일치가 크래시 없이 위치 있는 에러가 된다 → Task 3 · 6

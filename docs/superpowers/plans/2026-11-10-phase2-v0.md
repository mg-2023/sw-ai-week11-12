# Phase 2 v0 기본 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase 1 의 diff · patch 위에 함수형 컴포넌트 · `useState` · `useEffect` · `useMemo` 를 얹고, 버전별 성능을 화면으로 보는 측정 페이지를 만든다.

**Architecture:** 상태가 바뀌면 루트 컴포넌트 함수를 다시 실행하고, 결과를 태그만 있는 트리로 펼쳐(`expand`) 컨테이너 태그로 감싼 뒤, 지난 트리와 Phase 1 `diff` → `applyPatches` 한다. 렌더마다 측정값을 `onCommit` 으로 보고한다.

**Tech Stack:** Vanilla JS (즉시 실행 함수 + `module.exports` / `window.MiniReact`), Node `node:test` + `jsdom` ^24.

**Spec:** `docs/superpowers/specs/2026-11-10-phase2-v0-design.md` — **7 절(검토 반영)이 4 절보다 우선.** 엣지 케이스 원본 : 볼트 `미니리액트/04 구현 기록/Phase 2 구현 워크플로.md` 「엣지 케이스」 1 ~ 8.

## Global Constraints

- 외부 프레임워크 · 빌드 도구 금지. 새 의존성 추가 금지 (devDependency `jsdom` 만).
- 모듈 모양은 Phase 1 과 같게 : `(function (root) { … })(globalThis)`, Node 는 `module.exports`, 브라우저는 `root.MiniReact = Object.assign(root.MiniReact || {}, api)`.
- 브라우저 로드 순서 : `src/vdom.js` → `src/diff.js` → `src/patch.js` → `src/hooks.js` → `src/component.js` → `phase2/app.js`.
- Phase 1 동작을 바꾸는 수정은 **선택 인자 · 기본값으로만** (예외 : `h()` 가 `true` 를 버림). 매 작업 끝에 `npm test` 전체 통과.
- 함수마다 한 줄 주석(무엇을 하는지). 이유는 설계 문서에.
- 커밋 메시지에 Claude · AI 표시(Co-Authored-By 등)를 넣지 않는다. push 금지.
- 측정 패널(②)은 엔진을 쓰지 않는 일반 DOM 코드.

## Review Focus

1. 할 일을 입력하는 도중 다른 상태가 바뀌어 다시 그려져도 입력값 · 커서가 유지된다 → Task 3 `입력 중 다시 그려도 값 유지`.
2. 목록 가운데 항목을 지우면 그 항목만 사라지고, 남은 항목의 [삭제] 버튼은 각자 자기 항목을 지운다 (index 비교 + 렌더마다 새 핸들러) → Task 4 `가운데 삭제 뒤 핸들러가 맞는 항목을 가리킴`.
3. `setState` 를 10 번 연달아 부르면 최종 값이 맞고 렌더가 10 번 일어난다 (Batching 없음이 숫자로 보임) → Task 3 `연속 10번`.
4. deps 가 있는 effect 안에서 `setState` 해도 무한 루프 없이 한 번만 더 그린다 → Task 6 `effect 안 setState 는 한 번`.
5. 컴포넌트가 렌더 중 예외를 던지면 화면이 그대로이고, 그 뒤 정상 `setState` 는 동작한다 → Task 3 `렌더 예외 뒤 복구`.

### Task 3 (M3): `setState` → `update()` · 예외 복구

**Files:** Modify `src/hooks.js`, `src/component.js` · Test `test/update.test.js`

**Interfaces:**
- Produces: `update()` — 렌더 → `diff(이전, 새, stats)` → `applyPatches(container, patches)` → `syncFormState(…, {controlledOnly:true})` → effect → 보고(`kind:'update'`). 컴포넌트 상태 `phase`: `'idle' | 'render' | 'commit'`, `destroyed`

- [ ] **Step 1: 실패하는 테스트**
	- 클릭 → `setCount(c => c + 1)` → 글자가 바뀌고, **바뀐 글자 노드 외 요소는 같은 객체** (`===`)
	- 같은 값 `setState` → 보고 안 불림 (`Object.is`, `NaN` · `+0/-0` 포함)
	- 함수형 업데이트 두 번 연달아 → +2
	- **연속 10번** : `for (10) setN(n => n + 1)` → 값 10, 보고 10 번
	- 렌더 중 `setState` → 에러
	- `destroy()` 뒤 `setState` → 무시 (에러 없음, 보고 없음)
	- **렌더 예외 뒤 복구** : `n === 3` 이면 throw 하는 컴포넌트, `setN(3)` 이 에러 → 화면 그대로 · `inspect` 값 2 · 이어서 `setN(4)` 정상
	- patch 실패 : `applyPatches` 를 한 번 throw 하게 바꿔 끼운 뒤 update → 컨테이너가 새 vdom 대로 다시 그려지고 보고 `recovered: true`
	- **입력 중 다시 그려도 값 유지** : `value` 없는 input 에 `'abc'`, 다른 상태 변경 → 여전히 `'abc'`; `value` 있는 input 은 상태값
	- 핸들러만 바뀐 렌더 → 보고 `eventOnly >= 1`, 옛 리스너는 안 불림 (클릭 1 번 → 새 핸들러만 1 회)
- [ ] **Step 2 ~ 4:** FAIL → 구현 → `npm test` PASS
- [ ] **Step 5: 커밋** `setState 가 diff 와 patch 로 바뀐 곳만 다시 그리게 함`

### Task 6 (M6): `useEffect` · 커밋 중 setState

**Files:** Modify `src/hooks.js`, `src/component.js` · Test `test/effect.test.js`

**Interfaces:** `useEffect(fn, deps?)`; `hooks[i] = { kind: 'effect', deps, cleanup }`; 커밋 중 `setState` → `pendingUpdate = true`, 커밋 끝에 `update()` (연쇄 50 번 넘으면 에러 `'update loop'`)

- [ ] **Step 1: 실패하는 테스트**
	- 실행 시점에 DOM 이 이미 반영됨 (effect 안에서 `container.textContent` 가 새 값)
	- deps 없음 → 매 렌더; `[]` → mount 때 한 번; deps 바뀔 때만
	- 순서 : 이전 cleanup → 새 effect (기록 배열로 확인)
	- cleanup 이 함수 아니면 무시
	- **effect 안 setState 는 한 번** : `useEffect(() => { if (n < 1) setN(1) }, [n])` → 보고 2 번 (mount + update 1), 최종 1
	- deps 없는 effect 안 무조건 `setN(n + 1)` → 50 번 뒤 에러
	- `onCommit` 콜백 안 `setState` → 커밋 뒤 한 번 다시 그림
	- `destroy()` → 모든 cleanup 실행, 컨테이너 비움
	- effect 하나 throw → 다음 effect 도 실행, 모은 예외를 마지막에 던짐
- [ ] **Step 2 ~ 4:** FAIL → 구현 → PASS
- [ ] **Step 5: 커밋** `useEffect 를 patch 뒤에 실행하고 cleanup 순서를 지킴`

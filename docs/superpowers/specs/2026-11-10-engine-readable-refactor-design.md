# 엔진 코드 읽기 좋게 정리 — 짧은 설계

- 날짜 : 2026-11-10
- 브랜치 : `refactor/engine-readable` (로컬, push 하지 않음)
- 대상 : `src/hooks.js`, `src/component.js`

## 왜

- 사용자가 엔진 흐름을 코드로 따라가며 학습하려 한다
- 지금은 정상 흐름과 실패 처리가 한 함수 안에 섞여 있어 흐름이 안 보인다

## 목표 · 범위 밖 · 실패 기준

- 목표 : 위에서 아래로 읽으면 "처음 그리기 → 다시 그리기 → effect" 순서가 보인다
- 범위 밖 : 성능 · Batching · key · 새 기능 · Phase 1 파일(`vdom` · `diff` · `patch` · `history`) · `phase2/app.js`
- 실패 기준 : 동작이 바뀐다, 테스트 파일을 고친다

## 접근 (고른 것 : 가)

| 안 | 내용 | 결과 |
| --- | --- | --- |
| 가. 동작 그대로 구조만 정리 | 긴 함수를 이름 붙은 단계로 쪼개고 실패 처리를 정상 흐름 밖으로 | **사용자 선택** — 제출 코드와 테스트가 하나로 유지 |
| 나. 학습용으로 가볍게 | 실패 처리를 빼서 정상 흐름만 | 테스트를 지우거나 바꿔야 하고 제출 코드와 갈라져 탈락 |

## 구조

1. `component.js` 는 구역 네 개
	- 펼치기 : `normalize` · `callChild` · `expandAll` · `expand`
	- 정상 흐름 : `mount` · `update` 와 그 단계 (렌더 → diff → 커밋 → effect)
	- 실패 처리 : 값 되돌리기 · 통째로 다시 그리기 · 예외 모으기 · 커밋 중 setState 줄 세우기
	- 측정 보고 : `countPatches` · `report` · `onCommit` · `inspect`
2. `hooks.js` : `nextSlot` 을 "규칙 검사" 와 "칸 꺼내기" 로 나눔. `makeSetter` 의 단계별 갈래를 이름 붙은 함수로
3. 각 파일 맨 위에 흐름 지도 주석. 함수마다 한 줄 주석은 지금 방식 유지
4. 공개 API(`MiniReact` 에 붙는 이름, `module.exports`)는 그대로

## 사용자 승인 뒤 바꾼 것 (Claude Code 판단)

- 처음 설계는 펼치기를 `src/expand.js` 새 파일로 빼는 것이었다

- "테스트를 고치지 않는다" 가 우선이므로 `component.js` 안의 구역으로만 나눈다

  사용 방법
  
    
    
  1. 테스트 영역의 HTML 코드를 직접 고칩니다. (예: <li> 추가, class="done" 부여, <p> → <h3>, 글자 수정)
    2. 
    
  2. Patch: 테스트 영역의 HTML → 새 Virtual DOM → 이전 VDOM과 Diff → 변경된 부분만 실제 영역에 반영(노란 깜빡임) → State History에 저장.
    3. 
    
  3. 컴포넌트 모드: App 컴포넌트를 마운트하고 실제 영역 카드 아래에 카운터 버튼들이 생깁니다. +1을 누르면 setCount → 리렌더 → 이전 VDOM과 Diff → 바뀐 텍스트만 TEXT 패치로 반영됩니다. 소수 개수는 useMemo로 계산하므로 제목 강조처럼 카운터와 무관한 state만 바뀌면 다시 계산하지 않고(콘솔 로그로 확인), useEffect가 탭 제목 갱신과 자동 증가 타이머의 시작 / 해제를 맡습니다. 이 모드에서는 Patch · 뒤로 / 앞으로 · History 이동이 꺼지고 테스트 영역은 렌더 결과를 보여 주는 읽기 전용이 됩니다.
    4. 
    
  4. 뒤로 / 앞으로 (HTML 편집 모드): 저장된 VDOM으로 이동. 실제 영역은 두 State 사이의 Diff 패치로 바뀌고, 테스트 영역은 해당 VDOM의 HTML 코드로 바뀝니다. State History 항목을 눌러도 같은 방식으로 이동해요.
    5. 
    
  5. 컴포넌트 모드에서는 State History를 보기만 할 수 있어요. state는 훅 배열이 관리하므로, VDOM만 되돌리면 화면과 state가 어긋나기 때문입니다.
    6. 
  

  
이 구현은 key 없이 “같은 위치끼리” 비교합니다. 보안을 위해 script/style/iframe 등과 on* 속성, javascript: 링크는 VDOM 변환에서 제외돼요.
